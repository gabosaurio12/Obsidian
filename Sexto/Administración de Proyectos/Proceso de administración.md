La administración efectiva de un proyecto de software se enfoca en las cuatro **P**: _**P**ersonal_, _**P**roducto_, _**P**roceso_, y _**P**royecto_.
## Personal
Cualquier persona que tenga algo que ver con el resultado exitoso del proyecto:
- Gerentes ejecutivos
- Gerentes de proyecto (técnicos)
- Profesionales
- Usuarios finales
- Clientes
## Producto
Los ingenieros de software se concentran en el desarrollo de productos de software que se vende a un cliente.
Antes de poder planear un proyecto se deben establecer _objetivos_ y el _ámbito_ del producto, las _restricciones técnicas_ y _administrativas_.
Se estima el _costo_, el _reisgo_, la _descomposición realista_ de las tareas del proyecto y un _calendario_ de proyecto.
## Proceso
Es un conjunto de actividades, acciones y tareas que se ejecutan cuando va a crearse algún producto de trabajo. (Pressman, 2010)
- **Actividad**: Busca el logro de un objetivo amplio, como comunicarse con los participantes.
- **Acción**: Conjunto de tareas que producen un producto importante de trabajo, como el diseño de la arquitectura.
- **Tarea**: Se centra en un objetivo pequeño, pero bien definido como realizar una prueba con un resultado.
- **Proceso de software**: Conjunto de actividades y resultados asociados que producen un producto de software. (Sommerville, 2009)
## Proyecto
Es aquel **proceso único**, que consiste en un conjunto de actividades coordinadas y controladas con fechas de inicio y finalización, llevadas a cabo para lograr un objetivo conforme con requisitos específicos, incluyendo las limitaciones de tiempo, costo y recursos. (ISO 10006)
### En resumen
- Proceso **único** constituido por subprocesos y actividades coordinadas con el objetivo de realizar uno o más productos
- Tienen una naturaleza temporal, tienen fechas de comienzo y terminación
- Tienen una cantidad de recursos determinada
- Necesitan una estructura organizacional con roles y responsabilidades predefinidos para realizar los productos apegados a:
	- Calidad
	- Plazos
	- Costos
- Lo único fijo es el cliente y sus necesidades (el producto debe satisfacerlas)

## Gestión de proyectos
- Su objetivo es canalizar el trabajo de los desarrolladores de forma eficiente y productiva, de manera que conduzca al éxito del proyecto:
	1. Describir los objetivos del proyecto
	2. Realizar estimaciones de costo y tiempo
	3. Identificar actividades, hitos y entregas del proyecto
	4. Supervisar el desarrollo del proyecto
	5. Asegurar la calidad del producto
	6. Controlar los riesgos y los cambios del proyecto
- Es una parte esencial de la Ingeniería de Software, es un proceso flexible:
	- Una mala gestión lleva al fracaso del proyecto (por costos mayores, calendario desfasado o requisitos sin cumplir)
- Los gestores de software son responsables de la planificación y temporalización del desarrollo
	- Supervisan que se lleve a cabo bajo los estándares requeridos, asegurando el ajuste al tiempo y presupuesto
### Plan de proyecto
- Define procesos, tareas (_calendario_)
- Mecanismos para valorar _riesgos_
- Mecanismos para controlar el _cambio_
- Mecanismos para evaluar la _calidad_
- _Personal_ que realizará el trabajo
- Definir _costos_
### Ciclo general de la administración de un proyecto
1. Redacción de la propuesta
2. Planificación y calendarización del proyecto
	- Riesgos
	- Calidad
	- Cambios
3. Estimacíon de costes del proyecto
4. Selección y evaluación del personal
5. Supervisión y revisión del proyecto
	- Riesgos
	- Calidad
	- Cambios
6. Redacción y presentación de informes
## Diferencias de un proyecto de software
- El producto es intangible
	- No se ven fácilmente los retrasos o progresos
- No existen procesos del software estándar
	- Varían por organización
- A menudo los proyectos grandes son únicos
	- Afectan los cambios tecnológicos
	- La experiencia no es suficiente
## Estructura del proceso de desarrollo de software (Pressman)
1. Comunicación
	- Colaboración con el cliente y participantes
	- Se definen objetivos y requisitos
2. Planeación
	- Mapa para el equipo de trabajo y plan del proyecto
	- Tareas a realizar, riesgos, recursos, productos y se programan las actividades
3. Modelado
	- Bosquejo que muestra cómo se ajustan los componentes, ayuda a entender los requisitos y a realizar un buen diseño
4. Construcción
	- Código y pruebas
5. Despliegue
	- Entrega del producto (completo o parcial)
	- Evaluación y retroalimentación
### Actividades sombrilla
Se realizan a lo largo del proyecto y ayudan a administrar y controlar el avance, la calidad, el cambio y el riesgo:
1. Seguimiento y control del proyecto de software
2. Administración de riesgo
3. Aseguramiento de la calidad del software
4. Revisiones técnicas
5. Medición
6. Administración de la configuración del software
7. Administración de la reutilización
8. Preparación y producción del producto del trabajo
## ¿Cuándo sabemos que se hizo un buen trabajo?
- Hasta que se entrega el producto de alta calidad a tiempo y dentro del presupuesto
- El _gerente de proyecto_ lo hace bien cuando alienta a trabajar en conjunto y de forma efectiva
	- Cuando enfoca su atención en las **necesidades** del cliente y la **calidad** del producto
