## Técnicas modernas de revisión de código

| Elemento                  | Revisión mediante Pull Requests (*Pull Request Review*)                                                                                                                                                                                                                                          | Revisión integrada con integración continua (*CI-Integrated Code Review*)                                                                                                                                                                                     | Revisión asistida por inteligencia artificial (*AI-Assisted Code Review*)                                                                                                                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Técnica**               | Revisión mediante solicitudes de integración (*Pull Requests* o *Merge Requests*).                                                                                                                                                                                                               | Revisión de código integrada con integración continua (*Continuous Integration*, CI).                                                                                                                                                                         | Revisión de código asistida por inteligencia artificial (*AI-Assisted Code Review*).                                                                                                                                                                                                        |
| **Propósito**             | Evaluar los cambios propuestos antes de incorporarlos a una rama principal, con el fin de detectar defectos, mejorar la calidad y mantener la coherencia del código.                                                                                                                             | Complementar la revisión humana con comprobaciones automatizadas que permitan detectar errores de compilación, fallos en pruebas y problemas de calidad antes de integrar los cambios.                                                                        | Apoyar la revisión mediante IA para identificar posibles errores, sugerir mejoras, señalar patrones problemáticos y proponer casos de prueba.                                                                                                                                               |
| **Momento de aplicación** | Después de desarrollar una funcionalidad o modificación y antes de integrarla al código principal.                                                                                                                                                                                               | Durante el desarrollo, especialmente cuando se publica o actualiza un cambio que activa el proceso automatizado de integración continua.                                                                                                                      | Durante la implementación y revisión de cambios, antes de su integración o cuando se necesita analizar código existente.                                                                                                                                                                    |
| **Participantes**         | Autor del cambio y uno o más revisores del equipo.                                                                                                                                                                                                                                               | Desarrollador que propone el cambio, revisores humanos y herramientas automatizadas de integración y pruebas.                                                                                                                                                 | Desarrollador, revisores humanos y una herramienta de IA que analiza el código.                                                                                                                                                                                                             |
| **Roles**                 | **Autor:** prepara el cambio y responde a los comentarios. **Revisor:** examina el código y propone correcciones. **Responsable de aprobación:** verifica que se cumplan los criterios establecidos, cuando corresponde.                                                                         | **Autor:** publica el cambio. **Revisores:** evalúan su calidad. **Sistema de CI:** ejecuta compilaciones, pruebas y análisis configurados. **Responsable de integración:** verifica que se cumplan las condiciones de aceptación, si existe este rol.        | **Autor:** proporciona el código y verifica las sugerencias. **Revisor humano:** evalúa los hallazgos. **Asistente de IA:** propone observaciones y posibles correcciones, sin asumir la responsabilidad final de aprobación.                                                               |
| **Procedimiento**         | 1. Crear una rama y desarrollar el cambio. 2. Publicar una solicitud de integración con su descripción. 3. Solicitar la revisión. 4. Examinar el código y registrar comentarios. 5. Corregir los problemas identificados. 6. Aprobar e integrar el cambio cuando cumpla los criterios definidos. | 1. Preparar el cambio. 2. Activar el flujo de CI. 3. Ejecutar compilaciones, pruebas y análisis automatizados. 4. Examinar los resultados. 5. Corregir los fallos. 6. Combinar los resultados automáticos con la revisión humana antes de integrar el cambio. | 1. Proporcionar el código y el contexto necesario. 2. Solicitar el análisis a la herramienta de IA. 3. Examinar las observaciones y sugerencias. 4. Comprobar si los hallazgos son correctos. 5. Aplicar las correcciones justificadas. 6. Ejecutar pruebas y completar la revisión humana. |
| **Nivel de formalidad**   | Semiformal; puede ser formal si el equipo establece aprobaciones obligatorias, listas de verificación y políticas de integración.                                                                                                                                                                | Semiformal o formal, según las reglas de CI, los controles de calidad y los requisitos de aprobación del proyecto.                                                                                                                                            | Semiformal; puede integrarse en un procedimiento formal de revisión, pero la asistencia de IA por sí sola no establece un proceso formal.                                                                                                                                                   |
| **Preparación previa**    | Contar con un cambio delimitado, una descripción clara, contexto suficiente, pruebas pertinentes y revisores adecuados.                                                                                                                                                                          | Configurar el repositorio, las herramientas de compilación, las pruebas automatizadas y las reglas que determinan si un cambio puede integrarse.                                                                                                              | Seleccionar una herramienta apropiada, proporcionar contexto suficiente y definir qué aspectos se revisarán. También deben establecerse criterios para verificar las sugerencias y proteger el código y los datos confidenciales.                                                           |
| **Evidencia generada**    | Comentarios asociados al código, solicitudes de cambios, respuestas, aprobaciones, historial de modificaciones y registro de integración.                                                                                                                                                        | Resultados de compilación, informes de pruebas, alertas de análisis estático, registros de ejecución y estados de aprobación.                                                                                                                                 | Hallazgos sugeridos por la IA, comentarios, posibles correcciones y resultados de las pruebas utilizadas para verificar las recomendaciones.                                                                                                                                                |
| **Ventajas**              | Facilita la revisión asíncrona, conserva la trazabilidad, promueve el intercambio de conocimientos y permite controlar los cambios antes de integrarlos.                                                                                                                                         | Detecta fallos repetibles de manera temprana, reduce la dependencia de comprobaciones manuales y proporciona resultados consistentes en cada ejecución.                                                                                                       | Puede acelerar el análisis inicial, sugerir casos límite y ayudar a identificar problemas que merecen una revisión más profunda.                                                                                                                                                            |
| **Limitaciones**          | Puede retrasar la integración si los cambios son demasiado grandes, faltan revisores o las discusiones se prolongan. La calidad depende del contexto y de la atención de los revisores.                                                                                                          | Requiere configuración y mantenimiento. Las pruebas pueden ser incompletas y un resultado satisfactorio no garantiza que el código esté libre de defectos.                                                                                                    | Puede generar falsos positivos, omitir errores o proponer cambios incorrectos. Requiere supervisión humana y medidas para proteger la propiedad intelectual y los datos confidenciales.                                                                                                     |
| **Escenario recomendado** | Proyectos colaborativos que utilizan Git, equipos que necesitan revisar cambios antes de integrarlos y repositorios con varios desarrolladores.                                                                                                                                                  | Proyectos con integraciones frecuentes, pruebas automatizadas y requisitos de calidad verificables antes de aceptar cambios.                                                                                                                                  | Equipos que desean complementar la revisión humana, analizar cambios extensos o recibir sugerencias adicionales durante la depuración y el mantenimiento.                                                                                                                                   |

### Consideraciones

- La revisión mediante *Pull Requests* es una modalidad de revisión moderna de código que permite registrar discusiones y controlar la integración de cambios
- La revisión integrada con CI combina la evaluación humana con comprobaciones automatizadas
	- La integración continua no sustituye la revisión por pares
- La revisión asistida por IA es una práctica complementaria
	- Las sugerencias generadas deben verificarse mediante razonamiento técnico, revisión humana y pruebas apropiadas
